## 2. Ваш анализ (пошагово)

### T1. Размер когорты (D1) — 0,5 дня
1. Отфильтровать архивные ТП на T0; посчитать абонентов всего и активных 30 дн.
2. Результат → Excel `Inputs!C5` (доля архива), `Inputs!C6` (доля активных); в коде — `BASE` в `model/assumptions.py`.

### T2. Сегментация (D2, D3, D9) — 2 дня
1. Сначала правилами (прозрачно для руководства):
   - S1: ARPU < 5 000 и ≤ 5 дней активности в месяц;
   - S5: ж ≥ 55 / м ≥ 60 (из любого сегмента — приоритет);
   - S2: без абонплаты (PAYG) или голос > 70% выручки;
   - S3: абонплата ниже ближайшего актуального ТП при использовании пакета ≥ 60%;
   - S4: остальные пакетные, в т.ч. с докупками.
2. Проверить устойчивость кластеризацией (k-means / GMM на стандартизированных признаках: ARPU, ГБ, минуты, % пакета, стаж, устройство).
3. Результат → `Inputs!C17:D21` (доли и ARPU) и `SEGMENTS` в коде.

### T3. Value-gap (D1, D3) — 1,5 дня
1. Для каждого архивного ТП подобрать ближайший актуальный ТП по пакету (ГБ, минуты).
2. Разница абонплат (с НДС) = «недоплата»; распределение фактического использования пакета.
3. Список ТП-кандидатов для A2 (недоплата ≥ 4 000 сум и использование ≥ 60%) и семейств для B3 (устаревшие, < N абонентов, высокая стоимость сопровождения).
4. Результат → `Initiatives` строки «Доля целевой группы» и «Повышение абонплаты» для A2/B3.

### T4. Естественный эксперимент февраля 2026 (D7) — 2 дня — **самый ценный анализ**
1. Тест: абоненты ТП, изменённых 03.02.2026 (без соцгруппы). Контроль: сопоставимые архивные ТП без изменений
   (подобрать по ARPU, стажу, региону; при необходимости — propensity score matching).
2. Difference-in-differences по оттоку, даунгрейду, ARPU, звонкам в КЦ: 3 мес. до vs 3 мес. после.
3. Результат → A2: `churn_incr`, `downgrade`, `downgrade_delta` (min / мода / max = P10 / P50 / P90 оценки).

### T5. База оттока (D4) — 0,5 дня
Месячный отток когорты по сегментам → `Inputs!C9`; признаки для будущей модели оттока B1.

### T6. Исчерпание и докупки (D3, D5) — 1 день
Доля абонентов, исчерпывающих пакет, и доля из них, докупающих сами → A4 `eligible_share`, `cannibal`, частота.

### T7–T9 (до HARD) — 2 дня
Мигранты (D10) → A7; домохозяйства (D11) → B2; «Mobil avans» (D12) → B5; устройства (D9) → решение по B4.

### T10. Параметры экспериментов (D6, D13) — 0,5 дня
CV ARPU по сегментам → `AB_Calculator!B5`; базовые уровни guardrails → пороги дашборда.

## 3. Шаблоны SQL (адаптировать под схему DWH)

```sql
-- D1: численность и выручка по тарифам на T0
SELECT t.tariff_code, t.tariff_name, t.status, t.closed_date, t.monthly_fee_gross,
       COUNT(DISTINCT s.sub_hash)                                   AS subs_total,
       COUNT(DISTINCT CASE WHEN r.revenue_net > 0 THEN s.sub_hash END) AS subs_active_30d,
       SUM(r.revenue_net)                                           AS revenue_net
FROM dwh.subscriber_snapshot s
JOIN dwh.tariff_catalog t ON t.tariff_code = s.tariff_code
LEFT JOIN dwh.revenue_monthly r ON r.sub_hash = s.sub_hash AND r.month = DATE '2026-10-01'
WHERE s.snapshot_date = DATE '2026-11-01'
GROUP BY 1,2,3,4,5;

-- D7: diff-in-diff по волне 03.02.2026
WITH grp AS (
  SELECT s.sub_hash,
         CASE WHEN s.tariff_code IN (/* коды изменённых ТП */) THEN 'test' ELSE 'control' END AS arm,
         s.social_exempt_flag
  FROM dwh.subscriber_snapshot s
  WHERE s.snapshot_date = DATE '2026-01-01'
    AND s.tariff_code IN (/* изменённые + сопоставимые неизменённые архивные ТП */)
)
SELECT g.arm,
       CASE WHEN m.month < DATE '2026-02-01' THEN 'pre' ELSE 'post' END AS period,
       AVG(m.revenue_net)                       AS arpu,
       AVG(CASE WHEN m.churn_flag THEN 1 ELSE 0 END)  AS churn_rate,
       AVG(CASE WHEN m.tariff_change = 'down' THEN 1 ELSE 0 END) AS downgrade_rate
FROM grp g
JOIN dwh.subscriber_monthly m ON m.sub_hash = g.sub_hash
WHERE g.social_exempt_flag = 0
  AND m.month BETWEEN DATE '2025-11-01' AND DATE '2026-05-01'
GROUP BY 1,2;

-- D3/D5: исчерпание пакета и самостоятельная докупка
SELECT u.month,
       AVG(CASE WHEN u.data_used_mb >= u.data_allowance_mb THEN 1 ELSE 0 END) AS share_exhausted,
       AVG(CASE WHEN a.addon_cnt > 0 THEN 1 ELSE 0 END)                       AS share_buying_addons
FROM dwh.usage_monthly u
LEFT JOIN (SELECT sub_hash, month, COUNT(*) AS addon_cnt
           FROM dwh.addon_purchases GROUP BY 1,2) a
       ON a.sub_hash = u.sub_hash AND a.month = u.month
WHERE u.sub_hash IN (SELECT sub_hash FROM cohort_t0)
GROUP BY 1;
```
